FlyDisk 使用帮助

机械硬盘块级缓存加速器 · 给慢盘加一层内存 + 硬盘缓存

简介

FlyDisk 是一款面向机械硬盘（HDD）的加速工具。它会接管你指定的那块 HDD，在它前面铺一层由内存和固态硬盘组成的缓存，把反复读取的「热数据」留在快盘或内存上，从而缓解机械盘寻道慢、随机读慢的老毛病。

它的做法是块级接管，即完全接管一整块物理硬盘：点「启动加速」后，程序把目标盘整盘脱机并独占，再通过本机的 iSCSI 目标把这块盘重新暴露给 Windows。Windows 会像平常一样挂上盘上原有的 NTFS 卷，原来的盘符也会回来。此后你对该 iSCSI 盘的读写都会先经过缓存层。

⚠ 使用前请知悉
  • 本软件处于 Beta 测试阶段，稳定性尚未充分验证，请勿用于重要数据。对于因此造成的损失，我们不承担任何责任。
  • 理论上存在游戏误封号可能，虽然可能性极小，但如果用于游戏加速，依旧务必先新开小号做至少一周高强度游戏的可行性验证。 
  • 停止加速后，目标盘会保持脱机、在系统里看不到，这是有意设计：盘归本程序独占，跨重启的缓存才敢采信。要还盘给系统，见「重新联机硬盘」。
  • 程序必须以管理员身份运行，否则无法把整盘脱机或独占打开。

快速上手

第一次使用，照下面五步走即可。

  1. 双击运行 FlyDisk，在 UAC 弹窗点「是」（如果有）。主界面出现。
  2. 点主界面中间的「启动加速」按钮，弹出「选择要加速的硬盘」对话框。
  3. 在列表里选择你想加速的机械硬盘，点「确定」。
  4. 程序开始启动，通常只需等待 5 秒左右，日志区会逐步打印进度。
  5. 中心按钮显示「停止加速」后，打开「此电脑」，确认盘一切正常。
  6. 开始使用你的硬盘，感受飞一样的速度。 
  7. 使用完成后可以点击「停止加速」即可使硬盘空载，或直接关机（稳定性未充分测试，不是非常推荐），下次再使用时重新进行「启动加速」流程

加速效果取决于你的访问是否「有热点缓存」。反复打开同一个软件、反复读同一批文件时最明显；全盘顺序读写这类没有重复的场景，加速收益有限。

目前不支持开机自启、自动加速，需要的话可以自己用 AI 随便贡献点代码 

两级缓存 L1 / L2

FlyDisk 的缓存分两层，术语统一叫 L1 缓存与 L2 缓存。

层介质特点断电后
L1 缓存（内存缓存）系统内存最快，容量小，根据整机内存占用自动淘汰不保留
L2 缓存（硬盘缓存）另一块盘（推荐使用SSD）比内存慢但通常容量大，跨重启保留保留

缓存怎么工作

我们目前只支持读缓存。当系统需要读取硬盘中的数据时：

系统默认行为：直接从源盘读取（会有少量内存缓存，但通常可以忽略）

我们的行为：优先从 L1 L2 中读取数据，若 L1 L2 中均没有对应数据，才回到源盘读取数据，并同时直接存放到 L1 中，按需存放到 L2 中以便下次读取到相同数据时的加速

L2 缓存是按需增长的：只有真正读到的数据才会写进 L2，容器也随写入逐步扩大，不会预先占满你设定的预算。

L2 能跨重启保留，但在上次出现非正常退出、目标盘被手动联机等情况后需要进行全量校验以保证数据不出错，启动时若发现问题，程序会弹窗让你选择。
⚠ 注意：在开启 L2 功能时，你有责任避免进行手动脱机、使用另一个电脑/双操作系统的另一个使用硬盘等会令 L2 和实际数据不一致的操作，这种操作我们的程序无法有效自动察觉，应手动触发一轮 L2 校验。如你不确定你的操作是否会导致上述问题，也应手动触发一轮 L2 校验。

启动加速与选盘

每次启动都要重新确认一次选盘——这是故意的：避免你改过配置后隔几天才启动、已经忘了上次选的是哪块导致的误操作选错盘，但再这一步默认选项是上次的选择。

列表怎么看

每一行长这样：

磁盘 0（C: , D:）    型号字样    （容量）

括号里是该盘上的盘符（一块盘可能对应多个卷、多个盘符，用英文逗号分隔）；脱机的盘通常是由于你加速过，没有盘符，那一格显示「脱机」。

目前仅能同时加速一整块物理硬盘，不单卷加速 。

盘信息区

选中一行后，下方会显示：

  • 第一行基本信息：字节/扇区 · 容量 · 序列号。
  • 接下来是「不能加速」的 ❌ 原因及排查方法（如果有）。
  • 再往下是一些性能相关的提示，建议关注一下。

设置界面

通过菜单「设置」打开。配置只在「启动加速」那一刻被实际应用，加速运行中不能修改设置。

iSCSI 监听端口

  • 监听端口：除非特殊需求否则一般不用改。默认 3260，范围 1–65535。只监听回环地址 127.0.0.1，供本机 iSCSI 发起程序连接。

L1 缓存设置（内存缓存）

  • 启用 L1 缓存：默认开启。关掉后不再用L1缓存，不影响 L2。
  • 开始淘汰阈值（内存使用率）：默认 80%。系统内存使用率超过它时，开始淘汰冷块以释放内存。
  • 停止缓存阈值（内存使用率）：默认 90%。若数据量过大无法及时淘汰，超过它时暂停接受新的缓存数据。需保持「淘汰 < 停止」。

L2 缓存设置（硬盘缓存）

  • 启用 L2 缓存：默认关闭。
  • L2 缓存盘：下拉列出当前可用的盘符。请选一块速度快性能好的 SSD。
  • 容量预算（GiB）：默认 8，范围 1–64。这是 L2 在缓存盘上最多占用的空间。可以随时修改：改大或改小时，程序会在启动加速前弹窗确认，已有缓存按新容量缩放保留（缩容会丢弃位置靠后的部分块，扩容则全部保留），无需清空重建。

    •  L2 不会预先占满空间：它以 64 MiB 的整块随实际写入逐步增长，用多少占多少，未用到的空间仍可交给缓存盘上的其他内容使用。

  • 保守线（L2 缓存占用率）：默认 80%，范围 50–99%。L2 占用率超过它后缓存接收策略转为保守。

预计额外内存：有些缓存以外的必要内存开销会随着缓存增多而增大，窗口底部会给出估算，请对照内存余量合理决策。

检查器

菜单「检查器」打开，用来观察当前运行状态、统计数据，以便确定加速有没有效果。顶部有两个页签：

简要页

  • 两个速度方框：「加速后读取」指加速后各种软件读取硬盘的速度；「源盘读取」指实际硬盘的繁忙程度/所有回源读取的速度
  • 命中情况指示条：L1 命中 / L2 命中 / 源盘读取的块数在不同时间尺度下的统计。源盘读取越少代表这段时间加速效果越好。
  • L1 内存水位条与L2 占用条。
  • 底部显示 iSCSI 连接数与快照时间。

详细页

使用时通常不需要关注，纯文字，排查问题时方便直接复制粘贴给 AI。

悬浮窗与置顶

  • 检查器最小化时，会变成一个 50×50 的悬浮窗方便随时查看加速情况：左右分半，用灰阶分别显示「加速后读取」与「源盘读取」速度。单击悬浮窗可快捷打开检查器。
  • 检查器恢复显示后，悬浮窗自动隐藏。
  • 不想要就直接彻底关闭检查器即可。 

校验 L2

当程序判断 L2 缓存的可信度存疑时强制进行。你也可以手动触发，但正常使用时通常没必要 。  

⚠ 注意：在开启 L2 功能时，你有责任避免进行手动脱机、使用另一个电脑/双操作系统的另一个使用硬盘等会令 L2 和实际数据不一致的操作，这种操作我们的程序无法有效自动察觉，应手动触发一轮 L2 校验。如你不确定你的操作是否会导致上述问题，也应手动触发一轮 L2 校验。

手动校验方法如下： 

  1. 菜单「校验 L2」→ 确认要校验的物理盘。
  2. 点「校验」：程序逐块比对 L2 缓存与源盘，可能需要几分钟，取决于你的 L2 占用情况。
  3. 结果显示「一致：N 块全部相同」或「不一致 N 块（错误率 …）」。
  4. 若发现不一致，可点「修复」：把源盘的数据回写到 L2 容器，把这些错乱的块修回来。
校验要对源盘做只读访问；因此不能在加速运行时进行——请先「停止加速」。校验过程可随时「取消」，取消不会破坏已有缓存。

重新联机硬盘（把盘还给系统）

停止加速后，目标盘保持脱机，系统不可见，以便下次加速使用。要把它交还给操作系统，有两种办法：

  • 菜单「重新联机硬盘」：列表只显示脱机盘，大概率都是你加速过的，选一块、确定即可一键完成。
  • 或者用 Windows 自带：磁盘管理 → 右键该盘 → 联机。如失败也可以咨询 AI 后使用命令行联机。
联机后，这块盘就脱离本程序控制了，可能被其他程序写入。如果你启用了 L2 缓存，下次启动加速需要强制校验 L2（可能花一两分钟）。程序会给出这条提醒。

远程加速（实验性）

⚠ 实验性特性：正在开发中，尚未经过充分验证。不保证功能可用（可能配不上对、可能中途断开、可能长时间无响应）；不保证数据安全（通道不加密；同意对端要盘时，本机会把整块物理盘脱机后交出去，对方写入的内容与程序自身的缺陷都可能损坏盘上数据）。不要使用，如果不小心点到请点击「取消」。

如果实在希望有这个功能可以去提交 issue 或者直接用 AI 给我们贡献一点代码 

远程功能用于把另一台机器上的一块物理盘，通过网络借到本机来加速（或反过来把本机磁盘借给对方）。

服务端（提供盘的一方）

  1. 打开菜单「远程」，在弹窗里选「开放远程服务（本机监听，等对方来配对）」。
  2. 填「监听端口」（默认 10808），点「开放远程服务」。
  3. 有客户端请求使用某块盘时，本机会弹窗请你确认「是否信任并同意脱机」。

客户端（使用盘的一方）

  1. 选「配对远程服务（连接到对方）」。
  2. 填「对端地址」，格式为 主机:端口（例如 192.168.1.5:10808），点「配对远程服务」。
  3. 配对成功后，点「启动加速」会列出对端的磁盘清单，选一块即可。之后与本地加速的操作一致。

断开与提醒

  • 点「断开」结束配对。
  • 仍处于配对状态时，关闭远程服务会被拒绝——请先断开配对。
  • 远程形态目前不支持逐块校验 L2；L2 不匹配时只能选择「清空重建」。
  • 任何能连到本机的人都能「列出」磁盘清单，但真正使用某块盘仍需你在弹窗上逐次确认。

托盘与退出

  • 加速运行中关闭主窗口：程序不退出，而是最小化到通知区（托盘），出现一个图标。检查器与悬浮窗不受影响，不会跟着最小化。
  • 单击托盘图标：把主窗口叫回来。托盘图标只在主窗口隐藏时出现。
  • 退出路径只有一条：先「停止加速」，再关闭主窗口，才会真正退出整个程序。

语言与主题

  • 语言：通过菜单「🌍 语言」切换。切换即时生效。默认跟随系统。
  • 主题：界面深 / 浅色跟随系统。应用图标会随主题切换；桌面快捷方式若已存在，其图标也会同步更新（程序只更新已有快捷方式，不会新建或删除）。

常见问题

停止加速后，那块盘在系统里不见了？

正常。停止加速后盘中保留「脱机并由本程序独占」的状态，这是为了跨重启缓存可信。再次使用只需再次加速即可。也可以用菜单「重新联机硬盘」或「磁盘管理 → 联机」即可还盘。见“重新联机硬盘”章节

启动时提示「L2 缓存不匹配」或「需要校验」？

这是两个不同的弹窗，按钮都是「是 / 否」，但含义相反，请按标题和正文写的那一条来判断：

  • 「L2 缓存不匹配」（这次选的目标盘与上次不是同一块）：「是」= 清空这份 L2 并重建（原缓存内容全部作废，之后重新学习）；「否」= 中止启动、不做任何改动（下次启动还会问）。这是在提醒你这次是不是选错了盘。
  • 「L2 缓存需要校验」（上次没正常关服、盘原本是联机状态等）：「是」= 现在开始校验（打开校验窗口逐块比对，可能要几分钟；校验干净后启动会带着这份 L2 继续）；「否」= 清空这份 L2 并继续启动。默认停在「是」。

拿不准时：在「不匹配」弹窗选「否」中止启动，再到菜单「校验 L2」逐块比对、修复后再启动，是最稳的一步。

启动时提示 L2 容量要放大 / 缩小，或说受缓存盘空间限制？

当你把「容量预算」改成与上次不同的值时，程序会在启动加速前让你确认：

  • 改小：缓存缩到新容量，超出部分（缓存中位置靠后的那些块）会被丢弃，其余保留。
  • 改大：已有缓存全部保留，新增的容量会在使用中逐步启用。
  • 受空间限制：缓存盘可用空间不足时，程序会为它保留约 1 GiB 空闲后再决定实际容量，可能比你设定的值小。留这段空闲是必要的——SSD 快满时读写会明显变慢，留出一些空间才能保证加速运行流畅。

以上情况都只是按新容量缩放、不会清空已有缓存；选「否」则中止启动、不改动任何东西。

提示「抢不到 L2 单实例锁」？

目标正在运行，或另一个 FlyDisk 实例正在使用这份缓存。请先点「停止加速」。

启动失败，说盘被占用 / 无法独占打开？

说明盘正在被使用，确认没有别的程序（备份软件、杀毒软件、另一个 FlyDisk 实例）正在使用该盘，再重试。

提示启动成功，但 iSCSI 没有自动挂载导致看不到盘？

可以到「开始菜单 → Windows 管理工具 → iSCSI 发起程序」手动连接启动，首次使用 iSCSI 发起程序 方法如下：

  1. 打开 iSCSI 发起程序
  2. 点击发现选项卡 → 发现门户(P) → IP地址填写“127.0.0.1”→ 确定(O)
  3. 点击目标选项卡 → 刷新(R) → 连接(N) → 确定
  4. 去此电脑中检查加速盘出现，使用一切正常 

如果依旧有问题可以将项目源代码下载下来拿着咨询 AI

FlyDisk Help

HDD block-level cache accelerator · a memory + disk cache in front of a slow drive

Overview

FlyDisk accelerates a mechanical hard drive (HDD). It takes over the disk you choose and puts a two-level cache (memory + SSD) in front of it, keeping frequently read "hot" data on the fast media — which mitigates the classic HDD weakness of slow seeks and slow random reads.

It works at the block level. When you press "Start Acceleration", the program takes the target disk entirely offline and exclusively, then re-exposes it to Windows through a local iSCSI target. Windows mounts the existing NTFS volumes just as before and your original drive letters come back. From then on, all reads and writes to that disk pass through the cache.

⚠ Please read first
  • This software is in Beta. Stability is not 100% guaranteed — do not use it with important data.
  • After you stop acceleration, the target disk stays offline and invisible to the system. This is intentional (the disk stays owned by the program so the cache survives reboots). See "Re-online a Disk" to give it back.
  • The program must run as administrator (the manifest requests it, so a UAC prompt appears), otherwise it cannot take the disk offline or open it exclusively.

Quick Start

Follow these steps for the first run.

  1. Double-click FlyDisk and click "Yes" on the UAC prompt (if any). The main window appears.
  2. Click the "Start Acceleration" button in the middle. The "Select the Disk to Accelerate" dialog opens.
  3. Pick the mechanical disk you want to accelerate and click "OK".
  4. The program starts up; it usually takes about 5 seconds, and the log box prints progress step by step.
  5. Once the center button shows "Stop Acceleration", open "This PC" and confirm the disk works normally.
  6. Start using your disk and feel the flying speed. 
  7. When done, click "Stop Acceleration" to idle the disk, or just shut down (stability has not been fully tested, so this is not strongly recommended); next time you use it, run the "Start Acceleration" flow again.

Speedup depends on whether your workload has "hot spots". Repeatedly opening the same app or reading the same files benefits most; a purely sequential full-disk read/write with no reuse gains little.

Start-on-boot and auto-acceleration are not supported yet; if you want them, you are welcome to contribute a bit of code with AI. 

Two Cache Levels: L1 / L2

FlyDisk's cache has two levels, uniformly called the L1 cache and the L2 cache.

LevelMediaTraitsAfter power-off
L1 cache (memory cache)System RAMFastest, small; evicted automatically based on overall memory usageNot kept
L2 cache (disk cache)Another disk (SSD recommended)Slower than RAM but usually larger; survives rebootsKept

How caching works

For now we only support read caching. When the system needs to read data from the disk:

Default system behavior: read straight from the source disk (there is a small amount of memory caching, usually negligible).

Our behavior: prefer reading from L1 / L2; only when the data is in neither do we fall back to the source disk, and then we store it directly into L1 and, as needed, into L2, so that reading the same data next time is accelerated.

The L2 cache grows on demand: only data that is actually read is written into it, and the container expands as it is written to — it does not occupy the whole budget up front.

L2 survives reboots, but after an abnormal exit last time, the target disk being manually brought online, or similar cases, a full verification is needed to make sure the data is correct. If a problem is found at startup, the program shows a dialog for you to choose.
⚠ Note: while L2 is enabled, it is your responsibility to avoid operations that make L2 and the actual data inconsistent, such as manually taking the disk offline or using the disk from another computer / another OS in a dual-boot setup. The program cannot reliably detect such operations automatically, so you should manually trigger a round of L2 verification. If you are unsure whether your operation could cause the above problem, you should also manually trigger a round of L2 verification.

Starting & Choosing a Disk

You confirm the disk every time you start — on purpose. Otherwise, after changing the configuration you might start days later and have forgotten which disk you chose, and pick the wrong one by mistake; the default option at this step is your previous choice.

Reading the list

Each row looks like this:

Disk 0 (C: , D:)    Model    (Capacity)

The parentheses hold the drive letters on that disk (a disk may map to several volumes and letters, separated by English commas). An offline disk usually means you accelerated it before, so it has no letters and that slot shows "offline".

For now you can accelerate only a whole physical disk at once; per-volume acceleration is not supported.

Disk info area

After selecting a row, the area below shows:

  • The first line of basic info: bytes per sector · capacity · serial number.
  • Then the ❌ reasons why it cannot be accelerated and how to troubleshoot them (if any).
  • Then a few performance-related hints — worth a look.

Settings

Open it from the "Settings" menu. The configuration is actually applied at the moment you press "Start Acceleration"; settings cannot be changed while acceleration is running.

iSCSI listen port

  • Listen port: normally no need to change unless you have a special requirement. Default 3260, range 1–65535. It listens only on loopback 127.0.0.1, for the local iSCSI initiator to connect.

L1 cache settings (memory cache)

  • Enable L1 cache: on by default. Turning it off stops using the L1 cache; it does not affect L2.
  • Eviction start threshold (memory usage): default 80%. When system memory usage exceeds it, cold blocks start being evicted to free memory.
  • Stop caching threshold (memory usage): default 90%. If too much data cannot be evicted in time and usage exceeds it, new cache data stops being accepted. Keep "eviction < stop".

L2 cache settings (disk cache)

  • Enable L2 cache: off by default.
  • L2 cache drive: a drop-down of the currently available drive letters. Choose a fast, high-performance SSD.
  • Size budget (GiB): default 8, range 1–64. The most L2 may occupy on the cache disk. You can change it at any time: when you grow or shrink it, the program asks for confirmation before starting, and the existing cache is resized to the new budget (shrinking drops the blocks at the tail end; growing keeps everything). No clear-and-rebuild is required.

    •  L2 does not occupy the space up front: it grows in 64 MiB whole blocks as data is actually written — it only uses what it needs, and the unused space stays available to other content on the cache disk.

  • Conservative line (L2 usage): default 80%, range 50–99%. Once L2 usage exceeds it, the admission policy switches to conservative.

Estimated extra memory: some necessary memory overhead beyond the cache itself grows as the cache grows; the bottom of the window gives an estimate — decide the budget sensibly against your free memory.

  • Restoring the inspector hides the floating window automatically.
  • If you do not want it, just close the inspector entirely. 

Verify L2

It is forced when the program judges the L2 cache's trustworthiness to be in doubt. You can also trigger it manually, but in normal use it is usually unnecessary.  

⚠ Note: while L2 is enabled, it is your responsibility to avoid operations that make L2 and the actual data inconsistent, such as manually taking the disk offline or using the disk from another computer / another OS in a dual-boot setup. The program cannot reliably detect such operations automatically, so you should manually trigger a round of L2 verification. If you are unsure whether your operation could cause the above problem, you should also manually trigger a round of L2 verification.

To verify manually: 

  1. Menu "Verify L2" → confirm the physical disk to verify.
  2. Click "Verify": the program compares the L2 cache against the source disk block by block; this may take minutes depending on how much L2 is in use.
  3. The result reads "consistent: all N blocks equal" or "N inconsistent blocks (error rate …)".
  4. If inconsistencies are found, click "Repair": it writes the source data back into the L2 container and fixes those scrambled blocks.
Verification reads the source disk read-only, so it cannot run while acceleration is active — stop first. You can "Cancel" at any time; cancelling does not damage the existing cache.

Re-online a Disk (give the disk back to the system)

After stopping acceleration the target disk stays offline and invisible to the system, ready for the next acceleration. To give it back to the OS, there are two ways:

  • Menu "Re-online Disk": the list shows only offline disks — most likely the ones you accelerated. Pick one and confirm to finish in one click.
  • Or use the Windows built-in: Disk Management → right-click the disk → Online. If that fails, you can also consult an AI and bring it online from the command line.
Once online, the disk leaves this program's control and may be written by other programs. If you have L2 enabled, the next start of acceleration will force an L2 verification (may take a minute or two). The program gives you this reminder.

⚠ Experimental feature: under development, not yet fully validated. If you really want this feature, you can submit an issue, or just contribute some code to us with AI. 

Remote acceleration is for borrowing a physical disk from another machine over the network to accelerate locally (or, conversely, lending this machine's disk to a peer).

Server side (the one lending the disk)

  1. Open the "Remote" menu and choose "Open remote service (listen here, wait for the peer)".
  2. Enter the listen port (default 10808) and click "Open remote service".
  3. When a client asks to use a disk, this machine prompts you to confirm "trust and take offline".

Client side (the one using the disk)

  1. Choose "Pair with remote service (connect to the peer)".
  2. Enter the peer address as host:port (e.g. 192.168.1.5:10808) and click "Pair".
  3. Once paired, "Start Acceleration" lists the peer's disks; pick one. From there it works like local acceleration.

Disconnecting and caveats

  • Click "Disconnect" to end pairing.
  • While still paired, closing the remote service is refused — disconnect first.
  • Remote mode does not support block-by-block L2 verification; on a mismatch the only option is clear-and-rebuild.
  • Anyone who can reach this machine can list disks, but actually using one still requires your per-request confirmation.

  • Single-click the tray icon to bring the main window back (the icon then disappears). The tray icon appears only while the window is hidden.
  • There is only one exit path: stop acceleration first, then close the window to really exit.

FAQ

The disk disappeared from Windows after stopping?

Normal. After stopping, the disk keeps the "offline and exclusively owned by this program" state so the cache stays trustworthy across reboots. To use it again, just accelerate again; you can also use the menu "Re-online Disk" or "Disk Management → Online" to give it back. See the "Re-online a Disk" section.

"L2 cache mismatch" or "needs verification" at startup?

These are two different dialogs. Both use "Yes / No", but Yes means opposite things — judge by what the title and body say:

  • "L2 cache mismatch" (the target disk this time is not the same as last time): Yes = clear this L2 and rebuild (everything in it is discarded and re-learned); No = abort startup and change nothing (you will be asked again next time). This is a reminder in case you picked the wrong disk.
  • "L2 cache needs verification" (abnormal shutdown last time, the disk was originally online, etc.): Yes = start verifying now (opens the verify window and compares block by block, which may take minutes; if it comes back clean, startup continues with this L2); No = clear this L2 and continue startup. The default is Yes.

If unsure: in the "mismatch" dialog choose No to abort startup, then run "Verify L2" from the menu to compare block by block and repair before starting — that is the safest step.

At startup it says the L2 size will grow / shrink, or is limited by free space on the cache disk?

When you change the "size budget" to a value different from last time, the program asks you to confirm before starting acceleration:

  • Shrinking: the cache is resized to the new budget; the part beyond it (the blocks toward the tail of the cache) is dropped and the rest is kept.
  • Growing: the existing cache is fully kept, and the new capacity is brought into use gradually as you use it.
  • Limited by space: when the cache disk has too little free space, the program keeps about 1 GiB free for it before deciding the actual size, which may be smaller than the value you set. That free margin is necessary — an SSD that is nearly full slows down noticeably, so leaving some free space keeps acceleration smooth.

All of these only resize the cache to the new budget and never clear the existing cache; choosing "No" aborts startup and changes nothing.

"Could not acquire the L2 single-instance lock"?

The target is running, or another FlyDisk instance is using this cache. Click "Stop Acceleration" first.

Startup fails, saying the disk is busy / cannot be opened exclusively?

The disk is in use. Make sure no other program (backup software, antivirus, another FlyDisk instance) is using it, then retry.

It says startup succeeded, but iSCSI did not auto-mount so the disk is invisible?

You can go to "Start menu → Windows Administrative Tools → iSCSI Initiator" and connect manually. For first-time use of the iSCSI Initiator, the steps are:

  1. Open the iSCSI Initiator.
  2. Click the Discovery tab → Discover Portal (P) → enter "127.0.0.1" as the IP address → OK (O).
  3. Click the Targets tab → Refresh (R) → Connect (N) → OK.
  4. Check in "This PC" that the accelerated disk appears and works normally. 

If there are still problems, you can download the project source code and consult an AI with it.
