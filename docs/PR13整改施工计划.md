## 一、背景与结论

### 1.1 PR-13 做了三块事

| 块 | 内容 | 评价 |
| --- | --- | --- |
| A | **多盘同时加速**（`Form1.LocalSession` + `_extraSessions`，每盘一个 `TargetService`，端口/IQN 派生，L2 只给第一块） | 核心价值，方向正确，需按本计划改造失败语义 |
| B | **句柄共享冲突修复**（`ERROR_SHARING_VIOLATION`，属性/探针句柄改用 `FILE_SHARE_READ\|WRITE\|DELETE`，独占打开加重试且**不再降级**） | 正确，保留 |
| C | **开机自动化**（`StartupService` 计划任务 + `BootDiskPreparation` 开机保持脱机 + `--keep-offline-only`） | **本次整体归档**（见 §4），代码保留在 `docs/未启用-开机自动化/` |

### 1.2 评审结论（留 / 砍 / 改）

- **留**：多盘加速（改造后）、句柄共享修复、独占不降级。
- **砍（归档，不删除代码）**：整个「开机与自动化」。理由：
  1. 没有「开机自动加速」时，"登录后自动启动界面"只是省一次双击（仍要用户自己点「启动加速」选盘），不值一整套计划任务子系统；
  2. 「开机保持脱机」收益很窄（盘在稳态下本来就保持脱机），却破坏了 L2 的核心可信判据——"开机任务把一块原本联机的盘脱机"会把"曾经被系统挂载过"伪装成"一直脱机"；
  3. 它附带一串判据不全、弱身份可能指错盘、文案与判据不符等问题。
- **改**：
  - 克隆盘校验从"身份过滤 + 只告警"改成"**会话级、数量 ≥1 且全部健康**，失败整体终止"；
  - 失败语义统一成"**全成或全不成**"，删除"部分成功"；
  - 新增"无序列号 ⇒ 不能作为加速目标"的统一硬拦；
  - 修 `schtasks` 的 XML 读写与超时（修好后再归档，作为后来者的参考实现）。

## 三、第一步：R11 + R7 + R12（先修好，再归档）

> 本步只改 `FlyDisk/StartupService.cs`。此时功能仍是活代码，可以被验证。
> 目的：让归档出去的参考实现是"正确、可直接复用"的，而不是带着已知坑。

### 3.1 目标

1. 任务 XML 的**写**与**读**都使用 .NET 标准 XML API（`System.Xml.Linq`），不手写转义、不做字符串子串匹配；
2. 判据从"任务里是否含当前 exe 路径"升级为"**任务定义与期望定义一致**"（补全判据）；
3. `schtasks` 调用的 30 秒超时**真正生效**；
4. 任务 XML 不再落在 `%ProgramData%\FlyDisk\`。

### 3.2 写侧：`XDocument` 构造 + `XmlWriter` 落盘

**为什么**：现在 `BuildOfflineTaskXml` / `BuildStartupTaskXml` 用原始字符串插值 + 手工 `Escape()`，转义与编码都要人肉维护，加字段时容易漏。

**怎么改**：

- 新增命名空间常量（只定义一处，读写共用）：

```csharp
private static readonly XNamespace TaskNs =
    "http://schemas.microsoft.com/windows/2004/02/mit/task";
```

- 两个生成函数改为返回 `XDocument`：

```csharp
private static XDocument BuildOfflineTaskXml(string exePath);
private static XDocument BuildStartupTaskXml(string exePath);
```

  - 文档声明：`new XDeclaration("1.0", "utf-16", null)`；
  - 根节点：`new XElement(TaskNs + "Task", new XAttribute("version", "1.2"), ...)`；
  - 子节点用 `XElement` 逐个构造（内容与原字符串逐字段等价，**语义零变化**）；
  - `WorkingDirectory` 用 `Path.GetDirectoryName(exePath) ?? string.Empty`。

- `CreateTask` 签名改为接收 `XDocument`：

```csharp
private static bool CreateTask(string taskName, XDocument definition, out string error)
```

  落盘：

```csharp
var settings = new XmlWriterSettings { Encoding = Encoding.Unicode, Indent = true };
string file = ...;
using (var writer = XmlWriter.Create(file, settings)) definition.Save(writer);
```

  声明（`encoding="utf-16"`）与 BOM 自动一致。

- **删除 `Escape()`**（不再需要）。

> 等价的字段清单必须与原字符串**逐项对照**：`RegistrationInfo`（Author/Description）、`Triggers`、`Principals`、`Settings` 全量、`Actions/Exec`（Command/Arguments/WorkingDirectory）。**不允许顺手改动任何任务设置**。

### 3.3 读侧：字节流解析 + 投影比较

#### 3.3.1 为什么必须收原始字节

`schtasks /Query /XML` 的输出编码由 XML 声明决定（可能是 UTF-16LE）。现在的做法是 `ReadToEnd()` 成 string 再 `Replace("\0","")`，只能救 ASCII；中文路径会在解码这一步就烂掉，后面无论用什么解析器都救不回来。

因此：**stdout 收原始字节 → `XDocument.Load(new MemoryStream(bytes))`**，编码交给 XML 解析器判断。

#### 3.3.2 `RunSchtasks` 新形态

```csharp
/// 返回退出码（-1 = 启动失败/超时）。stdout 为原始字节，stderr 为文本。
private static int RunSchtasks(IReadOnlyList<string> arguments, out byte[] stdout, out string stderr)
```

- stdout：`Task.Run(async () => { using var ms = new MemoryStream(); await process.StandardOutput.BaseStream.CopyToAsync(ms); return ms.ToArray(); })`；
- stderr：`process.StandardError.ReadToEndAsync()`；
- 两者**并发**读取（消除"先读完 stdout 再读 stderr"的管道互等隐患）；
- 再 `process.WaitForExit(SchtasksTimeoutMs)`。

#### 3.3.3 判据：`TaskDefinitionMatches`

```csharp
private static bool TaskDefinitionMatches(
    string taskName, bool keepOffline, string exePath, out string reason)
```

流程：

1. `schtasks /Query /TN <name> /XML`；`rc != 0` → 不一致（任务不存在/查询失败）；
2. `XDocument.Load(new MemoryStream(bytes))`；**解析失败 → 判不一致**（保守方向：重建）；
3. 用同一生成函数造"期望定义"：`BuildOfflineTaskXml(exePath)` / `BuildStartupTaskXml(exePath)`；
4. `Project(actual)` 与 `Project(expected)` 做**字符串全等**比较。

#### 3.3.4 `Project(XDocument)` 的字段清单

只投影"我们真正在意、且 Windows 会原样保留"的字段，按固定顺序拼成多行文本：

| 类别 | 字段 | 归一规则 |
| --- | --- | --- |
| 动作 | `Actions/Exec/Command` | `Trim()` |
| 动作 | `Actions/Exec/Arguments` | 缺失 → 空串；`Trim()` |
| 动作 | `Actions/Exec/WorkingDirectory` | 缺失 → 空串；`Trim()` |
| 身份 | `Principals/Principal[@id='Author']/UserId` | 见 §3.3.5 |
| 身份 | `.../LogonType` | `Trim()` |
| 身份 | `.../RunLevel` | `Trim()` |
| 触发（开机任务） | `Triggers/BootTrigger` 存在 + `Enabled` + `Delay` | `Enabled` 缺失按 `true` |
| 触发（登录任务） | `Triggers/LogonTrigger` 存在 + `Enabled` + `UserId` | `Enabled` 缺失按 `true`；`UserId` 同 §3.3.5 |
| 关键 Settings | `MultipleInstancesPolicy` | `Trim()` |
| 关键 Settings | `ExecutionTimeLimit` | `Trim()` |

**故意不参与比较**（一比就永远不等，等于每次重建）：

- `RegistrationInfo` 全部（Windows 会补 `Date`/`URI`/`SecurityDescriptor` 等）；
- 其它 `Settings` 子项（`Priority`、电池、空闲等：对行为影响小，且归一化差异多）；
- XML 属性顺序、空白、命名空间前缀。

> 判据**过严**会重现 R11 的症状（每次启动都重建）。所以先窄后宽：上表跑一轮确认不会误判，再考虑加字段。

#### 3.3.5 `UserId` 归一化

`schtasks` 回读时可能把"域\用户"规范化成 SID（SYSTEM 的 `S-1-5-18` 一般原样）。

做法：两者都翻译成**SID 字符串**再比较：

```csharp
private static string NormalizeUser(string raw)
{
    raw = (raw ?? string.Empty).Trim();
    if (raw.Length == 0) return string.Empty;
    try
    {
        SecurityIdentifier sid = raw.StartsWith("S-1-", StringComparison.OrdinalIgnoreCase)
            ? new SecurityIdentifier(raw)
            : (SecurityIdentifier)new NTAccount(raw).Translate(typeof(SecurityIdentifier));
        return sid.Value;
    }
    catch
    {
        return raw;   // 翻译失败（域不可达等）退回原样比较
    }
}
```

- 需 `using System.Security.Principal;`；
- 实现后请用户实测一次回读形态（见 §12），把结果记进归档 README。

#### 3.3.6 调用点改造

- `TaskExists`：只关心退出码 → 用丢弃 stdout 的重载；
- `SyncOfflineTask` / `SyncStartupTask`：`TaskPointsTo(...)` 改为 `TaskDefinitionMatches(...)`；
- `DeleteTask`：不读 stdout。

### 3.4 R7：超时真正生效

**现状问题**（`RunSchtasks`）：

```csharp
stdout = process.StandardOutput.ReadToEnd();   // 阻塞到子进程关闭 stdout（= 退出）
stderr = process.StandardError.ReadToEnd();
if (!process.WaitForExit(SchtasksTimeoutMs)) { Kill; }   // 恒为 true，死代码
```

只要 `schtasks` 永不退出（Task Scheduler 服务 hung、EDR/HIPS 挂起进程等），调用线程就**无限阻塞**：设置保存会冻住 UI；启动期维护任务永不完成，`StartTarget` 里等它的 `await` 也永不返回。

**改法**：按 §3.3.2 并发读 + `WaitForExit(timeout)`。超时路径：

1. `Kill(entireProcessTree: true)`；
2. `WaitForExit(2000)` 给进程收尾；
3. 给两个读取任务一个短的合并等待（例如 2 秒），失败就丢弃；
4. 落 `debug-security.log`，返回 `-1`；
5. **不留未观察异常**（读任务在流关闭后会结束或异常，异常一律吞掉）。

> 注意：本阶段**不把 `Apply` 挪到后台线程**（接线马上随归档删除），只保证超时本身生效。

### 3.5 R12：任务 XML 改到用户临时目录

- `CreateTask` 里目录改为：`Path.Combine(Path.GetTempPath(), "FlyDisk")`；
- `Directory.CreateDirectory` 后写入；
- `RunSchtasks("/Create", ...)` 返回后，在 `finally` 里**删除该 XML**；
- 为什么：避免"提升权限的进程从共享可写目录读文件去执行"这种结构性坏味道；也避免 `%ProgramData%\FlyDisk\` 里永久躺着两个 `.xml`（用户会误以为是配置）。

### 3.6 本地化

本步**不新增用户可见文案**；失败仍走 `startup.task.createFailed/deleteFailed`，不一致只落诊断日志。

### 3.7 第一步的验收（用户执行）

1. 编译通过；
2. 勾选任一开关并保存 → 系统里出现对应任务；`%ProgramData%\FlyDisk\` 下**没有** `.xml` 残留；
3. **再次启动程序** → 不重建任务（可用任务修改时间或日志确认）；
4. 把 exe 改名/移动 → 下次启动会重建；
5. 条件允许时，把 exe 放到含 `&` 或中文的路径再验一次（旧实现会误判的两种情形）；
6. 手工跑一次 `schtasks /Query /TN \FlyDisk\AutoStart /XML`，确认回读的 `UserId` 形态（记进归档 README）。

> 功能验证是可选的（这段代码随后归档），但既然目的是"铺路"，跑一遍更稳。

### 3.8 风险

| 风险 | 对策 |
| --- | --- |
| 解析失败被当成"一致" | 一律判不一致 → 重建（保守） |
| 超时后读取任务未结束 | Kill + 短暂等待 + 丢弃；异常吞掉 |
| 判据过严导致反复重建 | 投影字段限于 §3.3.4；`RegistrationInfo` 等不比较 |
| `UserId` 回读形态随机器不同 | SID 归一 + 实测；翻译失败退回原样 |
| 命名空间写错导致查询全落空 | 常量只定义一处，读写共用 |
| 任务 XML 字段与旧字符串不等价 | 逐字段对照（§3.2），不允许"顺手改设置" |

## 五、第三步：R1 会话级校验 + 全成或全不成

### 5.1 引擎侧（`FlyDisk/Engine/TargetService.cs`）

#### 5.1.1 删除 PR 的身份过滤

- 删 `LooksLikeCloneOfThisSource`（L853）；
- 删 `InspectNewDisk`（L807）里插入的过滤块（"与本源盘不符则忽略"）。

**为什么**：过滤基于"型号 + 容量"，而克隆盘回读的型号是被 INQUIRY 截断到 16 字符的产品串，与源盘完整串不相等 ⇒ 自己那块也可能被滤掉（假阴性）；而会话级校验已经不需要身份判据。

#### 5.1.2 `CheckCloneDisk` 改成"判定 + 失败"

- 保留轮询（`CloneDiskPollMs = 250`），**保险丝改为 10 秒**（`CloneDiskWaitMs` 改名或直接改值）；
- 语义：
  - 一旦 `appeared.Count > 0`：对**当前出现的每一块** `Probe`；
    - 全部 `IsOnline == true` 且 `IsReadOnly == false` → 通过；
    - 任一块脱机或只读 → 失败（原因：哪块、什么状态）；
  - 到保险丝仍 `appeared.Count == 0` → 失败（"自动登录成功但盘没进系统视野"）。
- **数量 ≥1 即可**：≥2 块且全部健康 → 视为正常（热插拔盘不误杀）。

#### 5.1.3 失败如何表达

- 新增专用异常类型（命名空间 `FlyDisk.Engine`）：

```csharp
public sealed class IscsiCloneCheckException : Exception
{
    public IscsiCloneCheckException(string message) : base(message) { }
}
```

- 在 `RunWithSource` 里：`if (_config.EnableAutoIscsiLogin) { ...登录...; string? problem = CheckCloneDisk(...); if (problem != null) throw new IscsiCloneCheckException(problem); }`
- **实现口径**：`StartLocalCore` 里分两个 catch：
  - `catch (IscsiCloneCheckException)` → `StopCore(restoreDeviceState: false)`（**刻意让源盘保持脱机**：整套重试只有从脱机状态起步才能绕开"冗余路径"判定），再上抛；
  - 其余异常 → `StopCore(restoreDeviceState: true)`（恢复成打开前的样子），再上抛。
- **删除** `CloneDiskWarning` 属性（L751）及其全部引用；
- 修正 `CheckCloneDisk` 顶部"跑在 UI 线程上"的过时注释（实际在 `Task.Run` 的池线程上）。

#### 5.1.4 自动登录开关

- `DiskConfig` 新增：

```csharp
/// <summary>是否自动用 iSCSI 发起端挂载目标（关闭后由用户手动挂载；便于调试与故障绕过）</summary>
public bool EnableAutoIscsiLogin { get; set; } = true;
```

- `RunWithSource` 里（**实现口径：登录失败直接在引擎抛异常**，由 `StartLocalCore` 现有的
  `catch → StopCore(restoreDeviceState: true) → throw` 回滚，盘恢复成打开前的样子）：

```csharp
if (_config.EnableAutoIscsiLogin)
{
    HashSet<int> disksBeforeMount = ScanProbedDiskNumbers();
    bool mounted = _initiator.Connect(... out string mountError);
    if (!mounted)
        throw new IscsiAutoLoginException(
            Locale.T("engine.start.autoLoginFailed", mountError, _config.TargetIqn, ListenEndpoint));
    string? problem = CheckCloneDisk(disksBeforeMount);
    if (problem != null) throw new IscsiCloneCheckException(problem);
}
// 关闭时：不登录、不检查克隆盘（没有登录就没有新盘）
```

- `IscsiAutoLoginException` 是**不可恢复**类型：`StartAllAsync` 的通用 `catch (Exception)` 直接整体终止，
  不会走"整套重试"（只有 `IscsiCloneCheckException` 才重试）。
- `Form1.BuildSessionConfig` **必须复制**该字段（见 §5.2.4 的字段完整性检查）；
- 原 `AutoMounted` / `AutoMountError` 两个属性随之删除（异常消息已携带诊断）；
  `Form1.LogAutoMountResult` 只剩两种情况：自动登录开着 → "已自动挂载"；关着 → "请手动挂载（IQN/端点）"。

### 5.2 Form1 编排

#### 5.2.1 新流程（伪代码）

```csharp
private async void StartTarget()
{
    await ... (已删除，不再等待维护)...
    // 1) 选盘（模态，多选）
    // 2) 记住选择（最后选择，仅用于预选）
    // 3) 上锁
    _targetOperationPending = true;
    _targetOperationStarting = true;
    RefreshStatus();
    try
    {
        var started = new List<StartedSession>();     // 本次尝试已启动的会话
        var failures = new List<string>();
        StartFailKind kind = await StartAllAsync(picked, runL2Preflight: true, started, failures);

        if (kind == StartFailKind.CloneDisk)
        {
            Log(Locale.T("main.log.cloneRetry"));
            await StopStartedAsync(started, failures); // 停止，盘保持脱机
            if (有追加的停止失败) { ShowStartFailure(failures); return; }   // 不能拿同一引擎再启一次
            await Task.Delay(CloneRetryDelayMs);      // 1 秒
            started.Clear(); failures.Clear();
            kind = await StartAllAsync(picked, runL2Preflight: false, started, failures);
        }

        if (kind != StartFailKind.None)
        {
            await StopStartedAsync(started, failures);   // 停不下来的原因也进 failures
            Log(Locale.T("main.log.startAborted"));
            // Cancelled（用户主动中止 L2 预检）不弹聚合窗；但若有停不下来的会话，仍要如实弹出
            if (kind != StartFailKind.Cancelled || failures.Count > 0)
                MessageBox.Show(聚合后的失败原因, Locale.T("dialog.startFailed"),
                    MessageBoxButtons.OK, MessageBoxIcon.Error);
            return;
        }

        // 全部成功：把额外会话登记进 _extraSessions（第一块就是 _target）
        foreach (var s in started) if (!s.IsPrimary) _extraSessions.Add(new LocalSession {...});
        Log(Locale.T("main.log.multiDiskSummary", picked.Count));   // "全部 N 块已启动"
    }
    finally
    {
        _targetOperationPending = false;
        _targetOperationStarting = false;
        RefreshStatus();
    }
}
```

要点：

- **会话只有整批成功才登记**：失败时不能留在 `_extraSessions`，也不能留 `_target` 在跑；
- `StartAllAsync` 逐块：L2 预检（首轮才做）→ `StartTargetCore` → 记录；任一块失败立即停止后续并返回失败类型；
- **`StartTargetCore` 不再弹窗**，只返回 `(ok, message)`；异常向上抛；
- 失败聚合：`失败原因 = "磁盘 N（型号）：<原因>"` 逐行拼接；
- `StartFailKind`：`None / CloneDisk / Other / Cancelled`。只有 `CloneDisk` 触发重试；`Cancelled` = 用户在 L2 预检里主动中止（不弹聚合弹窗，只记日志）。

#### 5.2.2 停止已成功会话

- 新增 `StopStartedAsync(List<StartedSession>, List<string> failures)`：
  - 对每个会话调 `engine.Stop()`（**不**恢复设备状态 → 盘保持脱机，符合 D5）；
  - 若被拒（还有别的 iSCSI 连接），落日志并重试少量次数（复用 `TryStopForCloneRecovery` 的"带重试停止单引擎"能力，重命名/泛化为 `StopEngineWithRetryAsync`）；
  - **停不下来的会话把原因追加进聚合失败列表**（用户不能以为已经全停了）；克隆盘重试前若出现这种情况，**放弃重试**、直接终止。
- **不**调用 `PhysicalDiskHandle.TryOnline`（D5：不联机）。

#### 5.2.3 删除的旧逻辑

- 删 `RecoverFromCloneDiskProblem`（L1728）与 `TryStopForCloneRecovery` 的"整套重来"语义（能力保留为 `StopEngineWithRetryAsync`）；
- 删 `StartOneDiskAsync` 里"主盘整套重来 / 额外盘只停自己"的两个分支；
- 删 `LogAutoMountResult` 里打印 `CloneDiskWarning` 的两行；
- 删"成功 N/M"的汇总逻辑（改为"全部 N 块已启动"）；
- 删 `main.log.multiDiskStartFailed` / `main.log.multiDiskCloneProblem` 的使用。

#### 5.2.4 `BuildSessionConfig` 字段完整性

- 新增字段 `EnableAutoIscsiLogin` 必须复制；
- 交付前对照 `DiskConfig` 全部属性逐项核对一次（阶段 1 时共 **22 项**；阶段 3 加入 `L2Disks` 后为 **23 项**，`BuildSessionConfig` 已逐项复制），**不允许漏**。

#### 5.2.5 失败分类表

| 失败来源 | 分类 | 行为 |
| --- | --- | --- |
| 登录失败（引擎抛 `IscsiAutoLoginException`） | 不可恢复 | 整体终止；文案引导关闭「启用自动 iSCSI 登录」后重试并手动挂载 |
| 克隆盘校验失败（脱机/只读/未出现） | 可恢复（已知 workaround） | 整体终止 → **整套重试一次** → 仍失败则终止 |
| L2 加载失败（`L2LedgerUnusableException`） | 不可恢复 | 整体终止；文案指向「L2 管理」或关闭 L2 |
| 块大小/只读/无身份/系统盘/分页文件盘等 `Rejected` | 不可恢复 | 整体终止 |
| L2 预检被用户取消 | 用户中止 | 视为本次失败 → 整体终止；不弹"启动失败"，只记日志 |
| 其它异常 | 不可恢复 | 整体终止；异常文本进聚合弹窗 + 诊断日志 |

### 5.3 验收

1. **多盘全成功**：日志"全部 N 块已启动"；状态栏"多盘同时加速：N/N"；停止按钮"停止加速（全部 N 块）"。
2. **故意让一块失败**（如第二块选一块只读盘 / 手工关闭自动登录后模拟登录失败）：
   - 已启动的会话全部被停掉；
   - **盘保持脱机**（不自动联机）；
   - 只弹**一次**聚合弹窗，说明是哪块盘、什么原因；
   - `_extraSessions` 为空。
3. **第二块在 L2 预检点取消**：已启动的会话全部停止、盘保持脱机；**不弹聚合窗**（预检自己已说明），只记日志。
4. **克隆盘类失败**（若可复现）：能看到"正在重试"日志，且只重试一次。
5. **关闭「启用自动 iSCSI 登录」**：target 起来但不自动挂载；日志提示手动挂载；不报"挂载失败"。

- **`RemotePeer`**：空身份 ⇒ 对端匹配失败；但我们在授权前已拒绝，用户能看到明确原因。
- **错误文案**要说清"不是 bug，是这块盘没有稳定身份（无序列号）"，并建议换一块盘。

### 14.2 阶段 3：L2 多容器 + 每盘自选 L2 卷

> **后续决策（2026-10-17）**：本节第 4、5 条的**旧布局迁移已取消**（代码已删除 `TryMigrateLegacy`、
> 旧配置继承与旧结构扫描）。新版启动时若发现 `<卷根>\FlyDisk.Cache\cache.dat|index.bin`，
> 弹窗询问是否删除；选「否」退出程序。下面保留原始设计作为历史依据。

**架构**：方案 2 —— 每块盘一份容器，容器内部格式**完全不动**。

1. 目录规则：`<卷根>\FlyDisk.Cache\<归属身份散列>\`（散列沿用容器头那套设备身份算法：`SsdCacheService.ComputeIdentity` / `L2Verifier.TryReadOwnerIdentity` 同源）；
2. 配置模型：`SsdCachePath` / `SsdCacheMaxBytes` 两个单值 → **按盘清单**（盘身份 + 该盘选的 L2 卷 + 上限）；`EnableSsdCache` 仅保留为旧配置迁移与远程兜底（**不再是总开关**）；
3. 每盘上限单独配置；容量判据：
   - **按配置上限判**（不看当前已用）；
   - 按卷分组：`Σ(该卷参与盘上限) ≤ 该卷可用空间 − 1 GiB + Σ(该卷参与盘容器已占用)`；
   - **超限 ⇒ 阻止启动**（不再静默夹取），只报"某卷超了多少 + 建议值"（不点名具体盘）；
   - 运行期容器增长到预算上限即停止增长（沿用"扩容失败只关扩容、不停用 L2"）；
4. 老配置迁移：读旧容器头的 **身份散列（偏移 24）** 与 **槽数（偏移 16）** → 得到"属于哪块盘 + 该盘上限"；零迁移成本给有序列号的盘；
5. **老布局自动整理**：`<卷根>\FlyDisk.Cache\cache.dat|index.bin|cache.lock` → `<卷根>\FlyDisk.Cache\<散列>\`；
   - **必须发生在"没账本 ⇒ 新建空缓存"判定之前**（否则老缓存被静默抛弃）；
   - 扫**所有卷**（不只当前配置的卷）；
   - 同卷 `File.Move` 是元数据操作；按文件逐个搬，幂等、崩溃可恢复；
   - 新旧位置都有 → 以新位置为准，旧的登记进「L2 管理」待清，不静默删；
   - 认不出身份（头部损坏 / v1 无身份）→ **弹窗告警让用户手动处理**，不搬、不删；
   - 整理失败 ⇒ **拒绝启动**，绝不"换个空缓存先跑"；
   - `L2Manage` / `L2Verify` 入口也要先跑整理；
6. `L2Verify`：按各盘自己的目录解析（候选仍按身份收窄）；
7. `BuildSessionConfig`：删掉 `EnableSsdCache = false`，改为每会话指向自己的容器目录；
8. 帮助文档补"降级预期"：新版把文件搬进子目录后，旧版会看不到而新建空缓存（丢缓存、不丢数据）。

### 14.3 阶段 4：新「L2 管理」界面 + 设置分栏

1. **「L2 管理」一扇窗**（放弃复用 `PickerForm`）：
   - 列表列：**盘 | L2 卷 | 上限 | 实占 | 状态**；
   - L2 卷 = 行内下拉；上限 = 行内输入；
   - **新建** = 列表末尾加空行（盘、卷、上限都空着等用户填；盘格是下拉，列出全部已识别盘，重复选同一块盘时弹窗拒绝）；
     空行允许留空保存，但**启动时会拒绝"有盘但卷为空 / 上限无效"的条目**（不静默当成"不启用 L2"）；
   - **删除** = 移除行 + 一并清空该盘缓存文件（二次确认，明确写"会删除缓存文件"）；
   - **「清空缓存内容」** = 保留配置、丢掉缓存（真删干净，占用归 0；下次加速时引擎自动重建）；
   - **未识别**（容器头读不出/校验不过/无身份字段）：直接作为一行显示，盘="未知"、状态="未识别"、其余留空，**L2 卷与上限不可编辑**；
   - 超限提示**按卷**说（不点名具体盘）；
   - **关窗统一保存 + 「取消」不生效**；清空保留二次确认；「需校验」只在状态列显示，动作去菜单「校验 L2」；
   - 不显示"位置"列（路径只在"打开目录"内部使用）。
2. **设置窗口分「基础 / 高级」左右两栏**（`ThemedTabControl` 不用于此；纯左右布局）：
   - 基础：内存缓存（启用/淘汰线/停止线/预计额外内存）、SSD 缓存（摘要 + 「L2 管理…」）、保存/帮助；
   - 高级：iSCSI 端点（地址/端口）、L1 调参（窗口/宽限/批量）、L2 调参（保守线/ghost 倍率）、远程（端口/对端地址）、**启用自动 iSCSI 登录**；
   - 高级栏**不写解释性灰字**（解释归帮助文档）；`TraceFileLogging` **不进口 UI**（只能改 `config.json`）。
3. 帮助文档加"高级设置"中英双文章节。

### 14.4 归档功能复活的前提

若将来做「开机自动加速」，必须先补：

1. **L2 可信判据**：替用户脱机一块原本联机的盘 = 它被系统挂载过 ⇒ 该盘账本必须作废（先写标记、再脱机；UI 预检读标记即判不可信；处理完删标记）；
2. **无人值守的 L2 预检策略**（不能弹窗）：可恢复类默认"不采信、跳过该盘 L2"，不可恢复类整体终止；
3. 执行期完整判据（复用选盘框判定集合）+ 无稳定身份拒绝；
4. 按文档重新接回 §4.2 列出的接线点。
