| 阶段 | 内容 | 依赖 |
| --- | --- | --- |

## 一、阶段 2：会话平等化 + 检查器多盘

### 2.1 `Form1` 会话模型

**现状**：`_target`（第一块盘/远程）+ `_extraSessions`（第二块起），`IsPrimary` 分支散落在启动、停止、提示、刷新里。

**改成**：

- 新增：

```csharp
private sealed class Session
{
    public PhysicalDiskInfo? Disk { get; init; }   // null = 远程会话
    public required DiskConfig Config { get; init; }
    public required TargetService Engine { get; init; }
    public bool IsRemote => Disk == null;
}
```

- 唯一真相：`private readonly List<Session> _sessions = new();`
- 删除 `_target` 与 `_extraSessions` 的"特权"用法；保留一个** UI 默认选中会话**的只读入口：
  - `PrimarySession => _sessions.Count > 0 ? _sessions[0] : null`（仅供主界面状态栏 / 检查器默认选中 / 关闭提示使用，**不参与创建与成败判定**）；
  - `IsAnyTargetRunning` / `IsAnyTargetStopping` / `SessionCount` / `RunningCount` 全部遍历 `_sessions`；
  - 循环里不再有 `if (i == 0)` 的成败特判。
- **统一创建点**：

```csharp
private Session CreateSession(PhysicalDiskInfo? disk, int index)
{
    DiskConfig config = BuildSessionConfig(disk, index);   // index 0 也拿副本
    var engine = new TargetService(config);
    engine.OnInitiatorConnected += (i, e) => Log(Locale.T("main.log.iscsiConnected", i, e));
    return new Session { Disk = disk, Config = config, Engine = engine };
}
```

- `BuildSessionConfig(PhysicalDiskInfo? disk, int index)`：
  - index 0：端口/IQN 保持配置原值；index > 0：端口 = 配置端口 + index、IQN = 配置 IQN + `-{index+1}`（**外部语义与现在完全一致**）；
  - 由 `DiskConfig.Clone()` 复制全部属性（阶段 2 时 22 项；阶段 3 加入 `L2Disks` 后为 23 项），**不再持有全局 `_config` 本体**。
- `StartAllAsync`：逐块 `CreateSession` → `Start` → 记录到临时列表；**整批成功后**一次性 `_sessions.AddRange(...)`；失败路径统一 `StopStartedAsync` 并清空临时列表。
- `StopTarget`：遍历 `_sessions` 逐个 `Stop()`；成功后从列表中移除；「有连接就拒绝停止」仍由各引擎按自己的端口判定；`releaseDiskHint` 只在本地形态、至少停下一块时打一次。
- 关机路径 `OnFormClosing`：遍历 `_sessions` 调 `TryStopForShutdown()`。
- 远程形态：`FinishRemoteStartAsync` 用 `CreateSession(disk: null, index: 0)` 建一个远程 `Session`；`StopTarget` / 状态栏 / 检查器按同一套接口工作；本地与远程互斥逻辑不变。
- `LogAutoMountResult(TargetService engine, bool isPrimary)`：位置说明只对 `isPrimary` 打一次。
- **R2**：崩溃残留清理（`IscsiInitiator.CleanupStale`）改用 **IQN 家族**（按配置 IQN 前缀匹配），不再只清精确 IQN——端口/IQN 后缀变化留下的历史会话一并清掉。**未做**：当前仍是精确匹配、只清主 IQN（见 `TODO.md` 多盘条目第 ⑤ 条）。

### 2.2 检查器（`Inspector.cs`）

**目标（D16）**：

- **简要页**：顶部加「选择盘」下拉（只有 1 块时隐藏）；切换后显示该盘的同一套简要数据。
- **详细页**：**一屏依次列出所有盘**，每块盘的字段与现在完全一致，块之间用空行 + 「磁盘 N（型号）」标题分隔；整段文本可一次性复制。
- 数据源由 `Inspector(TargetService)` 改为：

```csharp
public Inspector(Func<IReadOnlyList<TargetService>> getEngines)
```

- 计时器每秒取一次快照列表；会话数变化时重建下拉项；已消失的会话从下拉里移除。
- **读速差分按会话各持一份**（`加速后读取` / `原盘读取` 是 UI 侧按秒差分出来的，不能共用一份历史值）。
- 打开检查器不再打「只显示第一块盘」的提示，删除 `main.log.inspectorPrimaryOnly` 及对应中英键。
- 远程形态仍只有一个会话，界面自动退化为单盘样式。

### 2.3 阶段 2 验收

- 单盘、多盘、远程三种形态启停/状态栏/菜单置灰与现在一致；
- 检查器简要页可切换盘，详细页能一次看到全部盘并可整段复制；
- 停止/关机时每个会话都被收尾；
- 全局搜索 `_target` / `_extraSessions` / `IsPrimary` 在 `Form1.cs` 中无残留。

## 二、阶段 3：L2 每盘独立容器与配置

### 3.1 配置模型

`DiskConfig` 新增：

```csharp
public sealed class L2DiskConfig
{
    public string DiskIdentity { get; set; } = string.Empty; // 型号|序列号
    public long OwnerHash { get; set; }                      // 设备身份散列（目录名）
    public string CacheVolume { get; set; } = string.Empty;  // "D:"（统一存盘符，不带反斜杠）
    public long MaxBytes { get; set; } = 8L * 1024 * 1024 * 1024;
}

public List<L2DiskConfig> L2Disks { get; set; } = new();
```

- `EnableSsdCache` / `SsdCachePath` / `SsdCacheMaxBytes` **保留为"旧版单盘字段"**，只用于升级迁移与远程兜底，**不清空**（远程没有按盘身份，仍靠它兜底）。
- `SsdConservativeThreshold` / `SsdCacheGhostFraction` 仍是全局高级参数。
- 同一 `DiskIdentity` 只允许一条；`CacheVolume` 为空（或 `MaxBytes <= 0`）= **配置不完整**，启动会被拒绝，补全后才启用。

### 3.2 目录结构

- 新结构：`<L2 卷根>\FlyDisk.Cache\<设备身份散列>\cache.dat|index.bin|cache.lock`
  - 散列沿用容器头那套设备身份算法（`SsdCacheService.ComputeIdentity(BlockSourceInfo)`，与 `L2Verifier` 同源），目录名为 16 位大写十六进制；
  - **容器头里的归属散列不变**（D9）。
- 旧结构：`<卷根>\FlyDisk.Cache\cache.dat|index.bin`（保持不变，仅作为迁移来源）。
- 新增引擎工具（`SsdCacheService`）：
  - `GetDiskCacheDirectory(string volumeRoot, long identity)`；
  - `GetLegacyCacheDirectory(string volumeRoot)`；
  - `TryMigrateLegacy(BlockSourceInfo source, string newDir, out string error)`：
    1. 新目录已有容器/索引 ⇒ 什么都不做；
    2. 旧容器不存在 ⇒ 什么都不做；
    3. 旧容器可识别且 `ownerIdentity == 本盘散列` ⇒ `File.Move` 容器与索引进新目录（同卷，等同改名）；
    4. 旧容器属于别的盘 / 无法识别 ⇒ 不动，记诊断日志、返回事实。
- 迁移时机：**该盘本次要启用 L2 的启动前预检**（不在 L2 管理扫描时搬文件）。

### 3.3 按盘解析与升级迁移

新增 `Form1.ResolveL2(PhysicalDiskInfo disk, out ...)`（或独立小类 `L2ConfigResolver`）：

1. 用 `PhysicalDiskHandle.DescribeIdentity` 找 `L2Disks` 条目；
2. 找不到条目：若旧结构容器存在且归属本盘 ⇒ **自动创建条目**（卷 = 旧目录所在卷，上限 = 容器头 `StoredSlots × 4 KiB`，取不到则用旧 `SsdCacheMaxBytes`），执行迁移，写回配置并记日志；否则视为不启用 L2；
3. 找到条目且 `CacheVolume` 非空 ⇒ 解析新目录，执行 `TryMigrateLegacy`；
4. 返回 `(enabled, cacheDir, maxBytes)`。

- 第一块盘不再有 L2 特权：`BuildSessionConfig(disk, index)` 对每块盘都调用上述解析，填 `EnableSsdCache / SsdCachePath / SsdCacheMaxBytes`。
- 旧的「L2 只给第一块盘」注释、分支与 AGENTS/TODO 表述一并删除。

### 3.4 启动前预检（每块盘各做一次）

`PrepareL2BeforeStart` 改为接收"已解析好的单盘 L2 配置"，顺序不变：

1. 容器属于本盘吗（`DetectLedgerMismatch`）；
2. 账本可信吗（盘原本联机 / 上次未正常关服 → 校验或清空；远程仍只能清空）；
3. **容量超限直接阻止启动**——
   - 标称槽数 = `ConfiguredSlotCountFor(resolvedConfig)`；实际可用 = `ComputeSlotCountFor(resolvedConfig)`；
   - 若实际 < 标称 ⇒ 中止启动，提示"L2 容量超过缓存盘可用空间：该卷最多还能用 X GiB，请到「L2 管理」把上限调到不超过该值"；
   - **删除静默夹取的确认弹窗**（`main.msg.l2ClampShrink/Grow/Same` 及代码路径）；引擎里的夹取仅作最后兜底（正常路径走不到）。
4. 容量变化（缩 / 扩确认保留；只有未超限时才问）。
- `ConfirmL2LedgerUnused` 同理按"本盘解析出的目录 + 旧目录"检查，避免漏掉旧结构账本。

### 3.5 L2 校验（`L2Verify.cs`）

- 入口选盘后，按该盘解析 L2 目录（新结构优先；只有旧结构则用旧目录原地校验，不搬文件）。
- `L2Verifier` / `L2VerifyForm` 仍接收 `DiskConfig`，但改为传**只含本盘 L2 路径与上限的副本**；不改 `L2Verifier` 内部逻辑。
- `TryReadOwnerIdentity` 的候选收窄改为遍历所有新/旧 L2 目录，按容器头归属散列匹配本地盘；0 匹配拒绝，1 匹配继续，多匹配（新旧并存）优先新结构。
- 「L2 管理」窗口里的校验入口（如果保留）同样按行解析目录。

### 3.6 扫描与描述（`SsdCacheService.DescribeAllL2Caches`）

- 对每个固定卷：
  - 旧目录 `<根>\FlyDisk.Cache`（若存在容器/索引）→ 一条 "旧结构" 记录；
  - 其**一级子目录** → 每条一份记录（新结构）；
  - 配置里 `L2Disks` 解析出的目录若未被扫到，补一条。
- `L2CacheInfo` 增补：`OwnerIdentity`、`IsLegacy`、`ConfiguredMaxBytes`、`DiskIdentity`；删除/保留 `IsConfigured` 由阶段 4 的 UI 使用。
- 扫描仍**只读**，不迁移、不加锁。

### 3.7 阶段 3 验收

- 两块盘分别配置到不同 L2 卷、各自独立容器；同时加速时两个 `cache.dat` 分别在各自目录；
- 旧版本留下的单份 L2：首次加速该盘时自动迁移到新子目录，缓存内容继续可用；
- 上限超过缓存盘可用空间 → 启动被阻止并给出建议值，不再静默夹取；
- L2 校验对每块盘都能找到自己的目录；
- 关闭 L2 的盘不会碰任何 L2 目录。

## 三、阶段 4：设置两栏 + 新「L2 管理」

### 4.1 设置窗口（`Settings.cs` / `Settings.Designer.cs`）

**布局**：左右两栏（不用选项卡），`ClientSize` **860 × 670**；底部左侧「帮助文档」、右侧「确定并保存」。

**基础（左栏）**：
- L1：启用 L1、开始淘汰阈值、停止缓存阈值；
- L2：只保留「L2 管理」按钮 + 一行摘要（例如「已为 N 块盘配置 L2」），**不再有 L2 盘下拉与容量数字**；
- 预计额外内存。

**高级（右栏）**：
- iSCSI：监听地址（新增）、监听端口、启用自动 iSCSI 登录；
- L1 调参：淘汰窗口（秒）、淘汰宽限（秒）、单次淘汰块数；
- L2 调参：保守线、ghost 倍率；
- 远程：监听端口、对端地址。

**约定**：
- 不写灰字解释（解释归帮助文档）；
- `TraceFileLogging` 不进口 UI；
- 删除 `settings.ssdDrive` / `settings.ssdSize` 等旧键，新增高级栏所需键（中英同步）。

### 4.2 「L2 管理」重做（`L2Manage.cs`）

单窗口配置表（标准控件行：`ComboBox` / `TextBox` / `Label`，不再使用 `DataGridView`），列固定为：

`盘 | L2 卷 | 上限 | 实占 | 状态`

- **盘的来源**：`L2Disks` 条目 + 扫描到的 L2 目录（新/旧结构）合并去重；
  - 已配置条目即使盘未连接也显示（状态「未连接」），卷/上限仍可编辑；
  - 未识别目录：盘显示「未知」、状态「未识别」，卷/上限只读；
  - 旧结构目录：状态「旧结构（该盘下次加速时自动迁移）」，只读。
- **L2 卷**：下拉框，列当前固定卷（盘符）；不排除目标盘本身，启动前仍由硬拦拒绝同盘。
- **上限**：输入框，单位 GiB，范围 1–64（卷非空时非法值阻止保存）；卷为空时整行按"未完成配置"保存，启动会被拒绝。
- **实占**：容器 + 索引的实际字节数；「清空缓存内容」后归 0。
- **状态**：已配置 / 未连接 / 无缓存 / 未配置 / 未识别 / 旧结构 / 待配置 / 已清空 / **未完成配置（启动会被拒绝）**。
- **按钮**：
  - 「新建」：直接加一行空行，L2 卷与上限都为空等待填写；盘的单元格为下拉框（列出全部已识别盘，重复选同一块盘时弹窗拒绝）；
    空行允许留空保存，但启动前会拒绝"有盘但卷为空 / 上限无效"的条目；
  - 「删除」：移除配置条目 **并清空该缓存目录的文件**（锁闸同 `TryClear`）；锁被占用则拒绝并保持原样；
  - 「清空缓存内容」：只删 `cache.dat` / `index.bin`，实际占用归 0，配置条目保留；
  - 「打开目录」；
  - 「确定」保存到 `DiskConfig.L2Disks` 并返回；「取消」丢弃本次改动。
- 同一盘身份只允许一行；保存时校验卷存在、上限合法。
- 旧 `L2ManageForm` 的单份缓存操作窗口与 `PickerForm` 的「L2 缓存」模式删除。

### 4.3 帮助文档与本地化

- 帮助文档（中英同步）：
  - 设置界面改为「基础 / 高级」两栏的新说明；
  - L2 改为每盘独立配置、在「L2 管理」里维护；
  - 说明旧缓存会自动迁移、上限超限会阻止启动；
  - 删除「设为当前缓存盘」等旧描述。
- 本地化：删除 `settings.ssdDrive/ssdSize`、`l2m.line.*`、`l2Clamp*` 等无用键；新增表格列、状态、按钮与提示键；中英 460+ 键保持完全对齐（脚本核对）。

### 4.4 阶段 4 验收

- 设置窗口左右两栏、无 L2 盘/容量控件、高级栏可改 L1 调参/地址/自动登录；
- L2 管理可新增、删除（含清缓存文件）、清空内容、打开目录；
- 未识别与旧结构行不可编辑；取消不落盘；
- 中英切换后新界面无缺键。

## 五、主要风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 会话列表化改动面大 | 高 | 先做阶段 2 并单独验证；全局检索 `_target` / `_extraSessions` / `IsPrimary` |
| 旧 L2 迁移搬错文件 / 搬丢 | 高 | 只在"容器头归属 == 本盘"时移动；移动前校验目标目录为空；失败只记日志并保留原文件；不删任何东西 |
| 配置迁移写坏旧配置 | 高 | 迁移只新增 `L2Disks` 条目；保存失败时保留旧字段（下次重试）；旧字段保留作远程兜底 |

| 阶段 3 与阶段 2 交叉返工 | 中 | 严格按 2 → 3 → 4 顺序，阶段 2 验收通过后再动 3 |

## 七、实施结果与已知偏差（2026-10-17）

已按阶段 2 → 3 → 4 全部改完，**未编译、未运行**。与计划的差异：

1. **配置迁移不清空旧字段**：`L2Disks` 生成后，旧版 `EnableSsdCache` / `SsdCachePath` / `SsdCacheMaxBytes`
   保留不动，作为**远程形态的兼容兜底**（远程没有本地盘身份，无法进入每盘配置表）。设置窗口已不再读写它们。
2. **旧结构迁移（后续已取消）**：见第 11 条；本项保留为历史记录。
3. **未识别 / 未知属主的行**：卷与上限均只读（未知属主无法写回 `型号|序列号`）。
4. **远程 L2**：仍走旧版单盘字段；本次没有做"远程盘也进每盘配置表"。
5. **L2 管理删除的落盘时机**：删除操作先只移除行，**点「确定」时才删文件**，因此「取消」不会误删。
6. **L2 管理改为标准控件行**：不再使用 `DataGridView`（其 ComboBox 提交/类型转换不可控）；
   动态加行后调用 `ThemeManager.Apply(this)`，与项目现有主题机制一致。
7. **`L2Verifier.TryReadOwnerIdentity`** 已无调用方（入口改为扫描所有目录 + 按归属散列收窄），暂留作只读探测工具。
8. **选盘框的 L2 拦截改为"多卷"**：`PickerForm` 的 L2 缓存盘参数从单个盘号改为盘号集合，
   由 `Form1` 按 `L2Disks` 里所有已配置卷折算——任何承载 L2 卷的物理盘都会被标成不能加速
   （没有条目时才回退旧版单盘字段）。
9. **R2 未实现**：阶段 2 计划的"崩溃残留按 IQN 家族清理"没有落地；当前仍是精确匹配、只清主 IQN
   （`IscsiInitiator.IsKnownTargetName` / `Program.CleanupStale`）。已从阶段 2 计划条目中标注为未做，保留在 `TODO.md` 第 ⑤ 条。
10. **L2 空配置改为拒绝启动**（2026-10-17 补定）：`L2Manage` 的新建行卷与上限**都留空**（不再预填第一个卷）；
    空行允许保存，但启动前 `Form1.ValidateL2ConfigForStart` 对"选了盘但卷为空 / 上限无效（`MaxBytes <= 0`）"的条目
    统一拦截并拒绝整批启动，不再静默当成"该盘不启用 L2"。
11. **旧布局迁移取消**（2026-10-17 补定）：不再扫描/迁移旧布局，`ResolveL2` 不再读取旧单盘字段做配置继承；
    `Program.Main` 启动时若发现 `<卷根>\FlyDisk.Cache\cache.dat|index.bin`，弹窗询问是否删除，
    选「否」直接退出程序。本文 §3.2 的迁移工具 `TryMigrateLegacy` 已删除。
