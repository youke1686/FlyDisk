# 停机改造与占用查询 · 施工计划

> 状态：**待确认**（本文档是计划，未开始施工）
> 对应 TODO：第二·后续功能中的「iSCSI 报错的详细处理」「硬盘占用时提供占用的程序的信息」
> 本文把这两条合并处理：停机语义改造 + 弹窗统一 + 占用查询（含 Handle2 源码并入）。

---

## 一、背景

当前「停止加速」只有一条路径，所有失败都汇总成一句笼统提示：

- 自动挂载的 iSCSI 会话登出失败，只把返回码写进 `debug-security.log`，界面拿不到；
- 停止被拒（本机监听端口上还有 ESTABLISHED 连接）时，界面统一显示同一句"请检查硬盘是否被程序占用"；
- 多盘同时加速时，每块盘的失败消息没有盘号，用户看不出是哪块盘出问题；
- 等在途命令有 2 秒上限，超时后整块收尾被推到后台，且**不提交 L2 账本**；
- 后台收尾 60 秒到点会"强行释放"，此时在途命令可能仍在跑。

本次要解决的是：把停止/强制停止的语义讲清楚、把 L2 账本尽量落下来、让用户能自己查到是谁占着盘。

---

## 二、目标与非目标

### 目标

1. 停机序列化简为一条：关命令入口 → 排空 → 落账本 → 释放。
2. 账本提交分**干净 / 脏**两态；等不到静止也落盘，标脏，下次启动要求校验。
3. 普通停止不再"超时放弃"，改为结构化失败 + 用户选择。
4. 新增「强制停止」，并在停止失败时可直接使用。
5. 新增「占用查询」，列出占用某块联机盘的程序。
6. 统一所有弹窗的格式与交互规则。

### 非目标（本次不做）

- 远程形态的占用查询（远程的盘在对端，本机查没有意义）。
- 可变缓存块大小、4Kn 扇区支持等 TODO 中的其他条目。
- 弹窗正文的全面文案审校（那是 TODO 里独立的长期任务，本次只做格式统一）。

## 四、停机序列

### 4.1 现状（供对照）

`TargetService.StopCore`（`FlyDisk/Engine/TargetService.cs:497`）：

```
_server?.Stop()
_disk?.Close()
bool idle = _disk.WaitForIdle(2000)
_source = null; _sourceInfo = null; _device = null;
if (!idle) {
    _cleanupPending = 1
    起后台线程：WaitForIdle(60000) → 无论结果 → ReleaseStoppedResources(persistLedger: false)
    直接 return
}
ReleaseStoppedResources(persistLedger: true)
```

`ReleaseStoppedResources`（同文件 568）：

```
cache.FreezeForShutdown()
cache.Shutdown(persistLedger)   // 落账本 + 清索引 + 归还 Slab + 关容器
device.Dispose() / RestoreAndClose()
```

`CacheService.Shutdown`（`FlyDisk/Engine/CacheService.cs:318`）内部依次：停水位节拍线程并 join → `_ssd.Close(persistLedger)` → 清空块索引 → 归还全部 Slab。

`SsdCacheService.Close(bool)`（`FlyDisk/Engine/SsdCacheService.cs:1894`）：`if (persistLedger) Flush()` → `_container.Dispose()` → `_lockFile.Dispose()`。

**问题**：落账本与释放内存/句柄是同一个调用，所以"超时后先落账本、稍后再释放"在现有结构下做不到。

### 4.2 目标序列

```
① 停 target                    _server.Stop()          不再接受新连接
② 关 LUN 后端                  _disk.Close()           之后命令一律 IOException
③ 等空闲                       WaitForIdle(2000)       仅用于判定干净/脏
④a 提交账本                    CommitLedger(clean|dirty)
④b 释放                        Release()
⑤ 关源盘独占句柄               device.Dispose()        盘保持脱机
⑥ 登出 iSCSI / 撤门户          位置见下：普通停止在前，强制/关机在后
```

**⑥ 的位置按路径不同**（这是本次唯一不统一的环节）：

- **普通停止**：⑥ 在 ① 之前，沿用现有顺序——先摘自动挂载的会话，让 Windows 侧有机会把文件系统刷干净并卸载，再做连接守卫。摘除失败时仍按现有口径 0s / 0.5s / 1s 重试三次。
- **强制停止 / 关机**：⑥ 放在 ⑤ 之后，后台尽力执行，失败只落日志。这两个路径本来就不等前端。

约束：

- **④b 与 ⑤ 必须完整执行到底**：要在 ③ 真正空闲之后开始；一旦开始，任何环节卡住就无限期等待，不设超时、不跳过、不提前返回。
- 取消 `CleanupWaitLimitMs` 的"到点强制释放"语义。保留一个间隔常量只用于日志（每 60 秒记一行"仍在等待在途命令退出"）。
- ④a 与 ④b 之间不等待，紧挨着执行。

### 4.3 三条路径的差异

| 路径 | ② 之前 | ③ 的用法 | 结果 |
| --- | --- | --- | --- |
| 普通停止 | 先 `IsIdle` 预检最多 2 秒；不空闲 → 直接返回失败，**未调用 `Close()`，全程无副作用** | 空闲后 `Close()`，此时 ③ 应为瞬时 | 干净账本 |
| 强制停止 | 不做连接守卫、不等前端 | `Close()` 后最多等 2 秒判定 | 超时则脏账本 |
| 关机 | 同强制停止 | 同强制停止 | 超时则脏账本 |

**普通停止的一个竞态也要写清**：预检通过、`Close()` 之后，仍可能有命令恰好进入（预检与 `Close()` 之间的窗口）。此时 ③ 若超时，按**强制语义**处理——落脏账本并继续等。不能因此回滚，因为 `Close()` 不可逆。

### 4.4 线程与资源约束

- 停止调用运行在 `Task.Run` 的后台线程上（`Form1.StopTarget`），内联等待不阻塞 UI。
- **不再另起收尾线程**：原 `FlyDisk.StopCleanup` 线程取消。这样"会话在收尾中仍在 `_sessions` 里"是天然的（`Stop()` 未返回），不会出现守卫丢失、端口/IQN 被复用的问题。
- `IsStopping` 保留，语义改为"正在收尾（④b / ⑤ 尚未完成）"，用于：
  - 状态栏显示 `engine.stop.pending`；
  - 阻止启动/联机入口给出"正在等待硬盘读写结束"的提示，而不是傻等生命周期锁。
- `TargetService._lifecycleLock` 在整个停止期间持有，别的会话的停止/启动会排队。这是已接受的代价（见第十一节）。

### 4.5 日志

| 时机 | 内容 |
| --- | --- |
| ③ 超时 | `在途命令 2 秒内未退出，本次账本将标记为脏` |
| ④a 脏提交成功 | `已写入脏账本（索引戳与容器戳不一致，下次启动需校验）` |
| ④a 干净提交 | `已写入账本（干净）` |
| 等待期间每 60 秒 | `仍在等待在途命令退出（已 N 秒）` |
| 强制停止开始时 | 主界面日志：`若长时间无响应，可直接通过任务管理器关闭本程序，不会影响数据安全。` |
| 任一步异常 | 保留现有 `LogService.DebugFile` 落盘 |

## 五、账本提交：干净 / 脏

### 5.1 可信判据（不改）

判据只有一条：**索引头 offset 52 的 `containerId` == 容器头 offset 8 的身份戳**，由 `SsdCacheService.LedgerStampMismatch` 实现。

`DetectLedgerMismatch` 是另一套判据（容器头魔数 / 版本 / 头部哈希 + offset 24 的设备身份），本次随 §8.4 一并删除，不再属于预检环节。

每次打开容器时 `_containerId = Random.Shared.NextInt64()` 重新生成，所以"上次没正常关服"天然表现为戳不符。

### 5.2 脏标记

- `WriteSnapshot` 增加参数：`bool dirty`。
- 写头部时：`hw.Write(dirty ? ~_containerId : _containerId)`。
- 其余字节布局、`INDEX_VERSION`、头部哈希、正文哈希、`index.tmp` + `File.Replace` 原子替换**全部不变**。
- `~_containerId` 与容器戳必然不等，因此下次启动一定被判为"上次没有正常关服"，走既有的校验流程。

### 5.3 脏路径的两条硬限制

1. **不调用 `_container.Flush(true)`**。容器是同一个 `FileStream`，此刻可能正有命令在写它，并发 `Flush` / `Dispose` 会出错。既然账本已经标脏、下次要逐块校验，容器数据是否已落到盘上不影响正确性。
2. **不 `Dispose` 容器、不释放目录锁**。这一步属于 ④b，必须等空闲。

**并发读索引数组**：`WriteRing` 读 `_mRing` / `_slotFlags` / `_slotBlockIndex` 时没有加锁，可能与在途命令的登记互相穿插。两种可能结果：

- 抛异常 → `Flush` 外层已有 try/catch，不产出索引文件 → 戳本来就不符 → 同样要求校验；
- 写出结构合法但语义半成品的条目 → 因为带脏标记，不会被直接采信，下次校验逐块比对时作废这些块。

两种情况都安全，区别只是"少一份近似索引"。

### 5.4 下次启动的处理（复用现有流程，不改）

`Form1.PrepareL2BeforeStart` 在 `untrusted.Length > 0` 时弹「L2 缓存需要校验」三分支：

- `校验` → 打开 `L2VerifyForm`，逐块比对容器与源盘，修容器并把戳写回自洽；
- `清空` → 删掉账本文件；
- `中止启动` → 不启动，不动任何东西。

> 注意：强制停止不是崩溃，但被判为"上次没有正常关服"。这是有意的简化，不做措辞区分。

- 在检查通过时，把本次新出现的盘号存进 `IReadOnlyList<int> CloneDiskNumbers`；
- 供两处使用：
  1. 占用查询的选盘框标注 `(加速中)`；
  2. 强制停止后"重新联机"的守卫——克隆盘仍在系统视野时拒绝联机（防同签名双盘）。

## 七、界面改动清单（停止相关）

### 7.1 停止失败：三分支

- **触发**：`Form1.StopTarget` 逐盘 `Stop()`，某块盘返回失败。
- **频率**：每块失败盘问一次（多盘时可能连续弹多次）。
- **标题**：`停止失败`
- **正文**：

```
磁盘 2（ST4000DM004）：还有 2 条 iSCSI 连接挂着这块盘。

确认：保持现状，之后可以再点「停止加速」。
检查占用：打开占用查询，找出正在使用这块盘的程序。
强制停止：立即断开所有连接并停止。

请选择其中一项。
```

- **按钮**：`确认` / `检查占用` / `强制停止`（最右固定"什么都不做"）。
- **关闭（X / Esc）**：等同 `确认`。
- **检查占用**：打开占用查询的选盘框，默认选中该盘（仍需用户点「开始检查」）。

### 7.2 强制停止

- 执行时在**主界面日志**写：

```
若长时间无响应，可直接通过任务管理器关闭本程序，不会影响数据安全。
```

- 成功后：移出 `_sessions`，盘**保持脱机**，不自动联机。
- 日志追加：`磁盘 N 已强制停止（账本：干净 / 脏）`。

### 7.3 多盘逐盘询问的交互

保持现有 `StopTarget` 的逐盘循环，只在失败分支插入三分支框；**不重排整体流程**。第一块盘等待用户时，后续盘的停止会被延后——已接受。

## 八、弹窗模板统一

### 8.1 五类模板

| 模板 | 用途 | 图标 | 按钮 | 标题 |
| --- | --- | --- | --- | --- |
| T1 告知 | 操作没有执行（前提不满足） | Warning | OK | `提示：<当前状态>` |
| T2 失败 | 操作已尝试但未完成 | Error | OK | `<操作>失败` |
| T3 确认 | 即将执行动作 | Warning | YesNo（"继续/取消"语义用 OKCancel） | `<动作>` |
| T4 分支 | 两个或多个选项各有后果 | Warning | 自绘（2–3 个） | `<情形>` |
| T5 崩溃 | 未处理异常 | Error | OK | `FlyDisk 遇到错误` |

### 8.2 通用规则

- 正文结构：结论一句 → 空行 → 明细（每行一个对象，格式 `磁盘 N（型号）：原因`）→ 空行 → 以"请"打头的收尾句。
- **不写"下一步："**。
- 后果段落以 `⚠️` 打头。
- 所有分支框（T4）：不设默认按钮；最右固定"什么都不做"；`Esc` 与关闭都等于它；Enter 不触发任何分支。
- T3（`MessageBox`）：YesNo 默认"否"，OKCancel 默认"取消"；T4 自绘、不设默认按钮，两者不要混为一谈。
- 除 T5 外全部传 owner。
- T5 不得依赖主窗体与 Locale（可能已失效），内部备中文字面量兜底。

## 九、占用查询

### 9.1 入口与三个框

```
菜单「占用查询」 ─────────────┐
                              ├→ 框1 选盘 → 框2 进度 → 框3 结果
停止失败 →「检查占用」 ───────┘（默认选中失败盘）
```

**框 1 选盘**（复用 `PickerForm`）

- 只列**联机**盘；加速中的盘追加 `(加速中)`；
- 单选；确定按钮文案为 `开始检查`；
- 取消 → 什么都不做。

**框 2 进度**（形态照 `L2VerifyForm`）

- `FixedDialog`，约 470×170，Marquee 进度条；
- 说明行：`正在枚举系统中的句柄并与卷设备路径比对…`
- 计数行：`已检查 N 个进程`（真实推进）；
- `取消`：协作式，粒度到一个进程；取消后立即关框，**不弹结果框**；
- 关闭窗口 = 取消，不二次确认。

**框 3 结果**

- 只读文本框（`Multiline` + `ReadOnly` + `ScrollBars.Both` + `WordWrap = false`），与检查器详细页一致，可直接选中复制，**不设"复制"按钮**；
- 可调整大小。

有结果时：

```
磁盘 3（ST4000DM004，4.0 TB）
检查时间：2026-10-23 14:02:31
共 2 个进程、7 个句柄；另有 3 个句柄无法读取

──────────────────────────────────────
notepad.exe（PID 8421）  2 个句柄
    C:\Windows\System32\notepad.exe

explorer.exe（PID 3120）  5 个句柄
    C:\Windows\explorer.exe
```

无结果时：

```
磁盘 3（ST4000DM004，4.0 TB）
检查时间：2026-10-23 14:02:31

未发现占用。

（盘仍可能因为文件系统挂载或系统服务在用。）
```

失败时：`检查失败：<原因>`。

### 9.2 枚举流程

```
1. 盘号 N
   └ FindFirstVolume / FindNextVolume 遍历所有卷
     └ 打开卷句柄，IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS
       └ 任一 extent 的 DiskNumber == N ⇒ 记下该卷的设备路径前缀 \Device\HarddiskVolumeK\
2. 取 File 对象类型索引
   └ 自己创建临时文件句柄 → NtQueryObject(ObjectTypeInformation).TypeIndex
3. NtQuerySystemInformation(SystemExtendedHandleInformation)
   └ 按 UniqueProcessId 分组
     └ 跳过本进程 PID
       └ 只处理 ObjectTypeIndex == File 类型索引的句柄
         └ OpenProcess(PROCESS_DUP_HANDLE) → DuplicateHandle
           └ NtQueryObject(ObjectNameInformation) → 原始设备路径
             └ 命中任一设备路径前缀 ⇒ 记入该进程
4. 聚合：进程名、PID、可执行路径、命中句柄数
```

约束与已知风险：

- **只对 File 类型句柄查名字**：`ObjectNameInformation` 对同步命名管道会永久挂起。
- 打不开的进程/句柄记为"未知"，计数进结果页，不隐藏。
- 取消检查：每个进程处理完检查一次 `CancellationToken`。
- 性能预估 1–3 秒（万级句柄），全程在后台线程。
- 已知待实测点：停止失败时克隆盘的卷**没有挂载点**时，卷枚举是否仍能取到设备路径。若取不到，退路是提示"无法定位卷"而不是假装无占用。

### 9.3 Handle2 源码并入

来源：`d:/projects/FlyDisk/Handle2`，MIT，Copyright (c) 2022 PolarGoose。

**并入的文件**

| 原文件 | 用途 |
| --- | --- |
| `src/Handle2/HandleInfo/Interop/NtDll.cs` | 句柄表查询、类型/名字查询、缓冲区重试 |
| `src/Handle2/HandleInfo/Interop/WinApi.cs` | `OpenProcess` / `DuplicateHandle` |
| `src/Handle2/HandleInfo/Utils/ProcessUtils.cs` | 进程名、可执行路径、属主 |
| `src/Handle2/HandleInfo/HandleInfoRetriever.cs` | 主循环，按我们的判据改写入口 |

**明确不并入**

- `DevicePathToDrivePathConverter`：它做"设备路径 → 盘符"，方向与我们相反；
- `GetProcessModules`：查 DLL 锁，与块设备占用无关；
- `Watchdog` + `WorkerThreadWithDeadLockDetection`：它的"检测到死锁"只是放弃等待，**worker 线程不会被终止**。CLI 退出无所谓，我们是常驻进程，会留下一条永久挂在内核里的线程。因此不用它，改为"只对 File 类型查名字"从根上避免挂起；
- `Fody` / `Costura` / `CommandLineParser` 等 NuGet：那是 CLI 打包用的。

**代码约定**：保留版权头与出处，命名空间改为 `FlyDisk.Engine`，文件放在 `FlyDisk/Engine/HandleScan/` 下；`THIRD-PARTY-NOTICES.md` 增加 MIT 条目。

### 9.4 结果渲染

按进程聚合，每进程一段；段内第一行 `进程名（PID N）  N 个句柄`，其下缩进写可执行路径。段与段之间空行。

## 十二、风险与已接受的取舍

| 项 | 说明 | 处置 |
| --- | --- | --- |
| 脏账本含半成品条目 | 冻结瞬间可能抓到未写完的槽位 | 带着脏标记，下次不会被直接采信；校验逐块作废 |
| 每次强制停止都要校验 | 逐块比对可能几分钟 | 已知的固有代价，接受 |
| 永不强放可能让进程卡在收尾 | 极端情况下盘一直脱机且被独占 | 已接受；提供"任务管理器关闭"提示；进程退出由 OS 回收，无堆破坏 |
| 关机被系统强杀 | 等待 + 写索引可能超出系统预算 | 已接受；留下 `index.tmp` 或旧账本，下次仍要求校验 |

| 句柄枚举挂起 | 同步命名管道 | 只对 File 类型查名字，从根上规避 |

## 十四、验证清单（交由用户在本机执行）

> 代理不编译、不运行。以下由用户操作并反馈。
> 可分阶段验证：阶段 2 完成后验第 9、10 条；阶段 3 完成后验第 1–8、12 条；阶段 4 完成后验第 11 条。

1. **正常停止**：加速一块未使用 L2 的盘 → 停止 → 日志显示"干净账本"，盘自动联机；使用 L2 的盘停止后保持脱机。
2. **普通停止被拒**：用记事本打开加速盘上的文件 → 停止 → 出现三分支框，正文含盘号与型号。
3. **检查占用**：在三分支框点「检查占用」→ 选盘框默认选中该盘 → 「开始检查」→ 进度框计数在涨 → 结果框列出 `notepad.exe`；结果可直接选中复制。
4. **取消检查**：进度框点「取消」→ 窗口关闭，不出现结果框，主界面仍可操作。
5. **强制停止**：三分支框点「强制停止」→ 主界面日志出现任务管理器提示 → 停止完成，盘保持脱机。
6. **脏账本**：制造一次"2 秒内有在途 I/O"的强制停止（例如持续读该盘）→ 停止后重启程序 → 启动预检要求校验。
7. **校验后恢复**：执行校验 → 校验通过后能正常带着 L2 启动。
8. **关机**：加速中点开始菜单关机 → 能正常关机；下次启动预检是否要求校验，与当时是否有在途 I/O 一致。
9. **菜单入口**：菜单「占用查询」→ 选一块未加速的联机盘 → 检查 → 结果合理。
10. **选盘框按钮文案**：逐个打开 L2 校验 / 重新联机 / 启动加速 / 远程 / 占用查询的选盘框，确认按钮文案分别是 开始校验 / 重新联机 / 启动加速 / 启动加速 / 开始检查。
11. **弹窗格式抽查**：删除 L2 缓存、清空缓存内容、实验性远程、旧版 L2 缓存四处，确认按钮文案、默认焦点、`Esc` 行为符合 §8.2。
